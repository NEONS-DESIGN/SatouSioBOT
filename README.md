## 🎵 概要
discord.py と yt-dlp を利用して構築された、レスポンスの速さを重視したDiscord用音楽Botです。
yt-dlp による解析を別プロセスで並列実行し、ローカルブラウザ（Firefox）のCookieを活用して安定した再生を行います。

## ✨ 主な機能

* **幅広いプラットフォーム対応**: YouTube、ニコニコ動画、SoundCloudなど、yt-dlp が対応するサイトのURL・プレイリストURL・曲名検索に対応。
* **高速な再生開始**: 応答・ボイスチャンネル接続・曲の解析を並行して進めます。解析は専用の子プロセスで行うため、解析中も Bot の応答が止まりません。
* **曲間の待ち時間を短縮**: 再生が始まった後に、キューの先頭2曲分のストリームURLを1曲ずつ順に先読みし、スキップや次曲への切り替えをすぐに行います。YouTube の曲はリプレイ・ループ時に取得済みのURLを使い回します。
* **検索・プレイリストの結果を保存**: 曲名検索で見つかった曲 (既定30日)、プレイリストの曲順、曲の情報 (既定半年) をデータベースに保存し、同じ曲名・プレイリストをもう一度再生するときは検索や取得を省いて再生を始めます。保存した曲を再生できなくなっていた場合は、自動で検索し直します。
* **軽量・再生優先**: 音量・速度の処理とエンコードは FFmpeg がまとめて行い、Bot 本体は音声を送るだけです。Windows では CPU の優先度を「再生中の曲 > 再生待ちの曲 > 次の曲 > それ以降の曲」の順に割り当て、先読みが再生を邪魔しないようにしています。
* **Cookieの自動参照**: `cookiesfrombrowser` で普段使用しているFirefoxのCookieを自動で読み込みます。年齢制限やログイン必須の動画も、手動でのCookie書き出し作業なしで再生できます。
* **サーバーごとの設定保存 (SQLite)**:
  * 再生音量、キューの最大数、プレイリストから追加する曲数、自動退出までの秒数をサーバー単位で保存。
  * Bot専用の操作権限 (Bot管理者) をDiscord上からコマンドで付与・剥奪可能。
* **見やすいUI**: Embedによる再生パネル、URLリンク付きのキュー一覧、ページ送りボタン付きのヘルプ画面。Botをメンションすると `/help` の案内を表示します。
* **聴者不在時の自動退出**: ボイスチャンネルから Bot 以外のメンバーがいなくなると、一定時間後 (既定10秒) に再生を止めて退出します。
* **毎日の自動再起動**: 長時間動かし続けると曲の読み込みが遅くなるため、毎日決まった時刻 (既定 0:00) を過ぎてから、どのサーバーでも使われていないときに Bot を自動で起動し直します。曲の解析用の子プロセスや Deno も新しく起動し直します。(`start.bat` から起動した場合のみ)
* **準備に時間がかかったときのお知らせ**: 「音源を準備しています...」の表示から20秒たっても再生が始まらない場合、待たせていることをお詫びする表示に切り替えます。
* **日付ごとのログ保存**: エラーやシステムログを日付ごとに自動分割して `log` フォルダに保存します。(30日分を保持) 通常はエラーと曲の読み込み状況のみを出力し、`config.ini` の `debug` を有効にすると処理時間などの詳細も出力します。
  * 曲の読み込みの開始・完了 (試行回数と所要時間つき)、再生の開始・終了を、時刻とサーバー名つきで1行ずつ出力します。複数のサーバーで同時に使っても表示が混ざりません。

## 💬 コマンド一覧
スラッシュコマンドとして使用できます。`/p 曲名` のように、通常のメッセージとして送信しても動作します。

### 再生・基本操作
| コマンド | 説明 |
|---|---|
| `/help` | コマンドの一覧と使い方を表示します。(本人のみに表示) |
| `/p [URL・曲名]` | 曲を再生します。再生中の場合はキューに追加します。プレイリストURLにも対応しています。 |
| `/pause` | 再生中の曲を一時停止します。 |
| `/resume` | 一時停止中の曲を再開します。 |
| `/replay` | 現在再生中の曲を最初から再生し直します。 |
| `/skip` | 再生中の曲をスキップします。 |
| `/speed [0.5-3.0] [ピッチ維持]` | 再生速度を変更します。再生中の曲にもすぐ反映されます。ピッチ維持を `False` にすると音の高さも変わります。Bot がボイスチャンネルから退出する (`/leave`・切断・再生終了) と1倍に戻り、チャンネル移動では維持されます。 |

### キュー・音量
| コマンド | 説明 |
|---|---|
| `/qlist` | キューに入っている曲を一覧表示します。(10件ごとにページ送り) |
| `/pnow [番号]` | キューの指定した番号 (`/qlist` の番号) の曲を今すぐ再生します。再生中だった曲は次の曲に回り、最初から再生し直します。 |
| `/clear [開始] [終了]` | キューの曲を削除します。引数なしで全件、`/clear 3` で先頭から3件、`/clear 2 5` で2〜5番目を削除します。 |
| `/loop` | キューのループ再生を切り替えます。 |
| `/sh` | キューの中身をシャッフルします。 |
| `/vol [1-200]` | 再生音量 (%) を変更します。再生中の曲にもすぐ反映されます。設定はサーバーごとに保存されます。 |

### Bot管理・設定
| コマンド | 説明 | 必要な権限 |
|---|---|---|
| `/move` | Botを自分のいるボイスチャンネルへ移動させます。 | - |
| `/leave` | Botをボイスチャンネルから退出させ、キューを削除します。 | - |
| `/purge [件数]` | チャンネルのメッセージを一括削除します。(1〜50件、既定50件) | メッセージの管理 |
| `/setting admin add/remove [メンバー]` | Bot管理者の付与・剥奪を行います。 | サーバー管理者 または Bot管理者 |
| `/setting limit queue [1-50]` | キューの最大曲数を設定します。 | サーバー管理者 または Bot管理者 |
| `/setting limit playlist [1-50]` | プレイリストURLから追加する最大曲数を設定します。 | サーバー管理者 または Bot管理者 |
| `/setting autoleave [0-600]` | 聴者がいなくなってから自動で退出するまでの秒数を設定します。(0 で自動退出しない) | サーバー管理者 または Bot管理者 |

> [!TIP]
> キューに曲が無くなったとき、またはボイスチャンネルに聴者 (Bot 以外のメンバー) がいない状態が設定秒数続いたとき、Botは自動でボイスチャンネルから退出します。

## 🛠 準備

### 1. 外部ソフトウェアのインストール
以下をインストールし、FFmpeg と Deno は環境変数 `PATH` を通してください。

| ソフトウェア | 用途 |
|---|---|
| [**Python 3.14.x**](https://www.python.org/downloads/) | Bot本体の実行 |
| [**FFmpeg**](https://www.ffmpeg.org/) | 音声のデコード・ストリーミング |
| [**Deno**](https://deno.com/) | YouTube の再生用署名の解読 (yt-dlp が使用) |
| [**Firefox**](https://www.mozilla.org/firefox/) | Cookie の参照元。**YouTube にログインした状態**にしておいてください。 |

> [!IMPORTANT]
> 高速化のため、YouTube の取得設定はログイン済みのCookieがあることを前提にしています。Firefox で YouTube にログインしていない場合、取得に失敗したり、予備設定に切り替わって遅くなったりすることがあります。

### 2. Discord Bot の作成
1. [Discord Developer Portal](https://discord.com/developers/applications) でアプリケーションを作成し、「Bot」ページでトークンを発行します。
2. 同じページの **Privileged Gateway Intents** で **MESSAGE CONTENT INTENT** を有効にします。(無効のままだと起動時にエラーになります)
3. 「OAuth2」→「URL Generator」で、スコープに `bot` と `applications.commands` を選択します。
4. Bot Permissions で以下を選択し、生成されたURLからサーバーに招待します。
   * メッセージを送信 / 埋め込みリンク / メッセージ履歴を読む
   * 接続 / 発言
   * メッセージの管理 (`/purge` を使う場合)

### 3. ライブラリのインストール
プロジェクトのフォルダで仮想環境 (venv) を作成し、必要なライブラリをインストールしてください。

```bash
py -3.14 -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
```

`start.bat` / `start.ps1` は `venv` があれば自動でそちらを使用します。venv を作らない場合は、`py -3.14 -m pip install -r requirements.txt` でインストールしてください。

## ⚙️ 設定ファイルの作成
以下のファイルを `main.py` と同じフォルダに配置します。`data.db` (SQLiteデータベース) は初回起動時に自動で作成されます。

### ① `.env` (Botトークン)
```env
discord_api = "あなたのDISCORD_BOT_TOKEN"
```

### ② `config.ini` (Bot動作設定)
リポジトリに同梱されています。必要に応じて値を変更してください。範囲外の値は自動で範囲内に丸められ、不正な値は既定値になります。

```ini
[MusicBot]
# 初期音量（0.0～2.0 の範囲で指定。1.0 = 100%）
default_volume = 0.25
# キューに入れられる最大曲数の既定値（1～50）
default_queue_limit = 50
# プレイリストURLから1回で追加する最大曲数の既定値（1～50）
default_playlist_limit = 10
# ボイスチャンネルに聴者（Bot 以外のメンバー）がいなくなってから自動で退出するまでの秒数の既定値（0～600。0 は自動退出しない）
# サーバーごとに /setting autoleave で変更できる
default_alone_timeout = 10
# ストリームURLの取得に失敗したときの最大試行回数
max_retries = 3
# yt-dlp で曲を解析する子プロセスの数（同時に解析できる曲数）。1 つあたり約 40MB のメモリを使う
# 先読みはサーバーごとに1曲ずつ行うため、1 サーバーで使うなら 2 で足りる。複数のサーバーで同時に使うなら増やす
max_worker_threads = 2
# プレイリストの取得結果を、取り直さずにそのまま使う秒数（例: 14400 は4時間。0 は毎回取り直す）
# 過ぎた後に同じプレイリストを再生するときは、保存した1曲目を先に読み込みながら最新の曲順を取り直す
cache_ttl = 14400
# 曲名検索の結果（どの曲が見つかったか）を保存しておく日数（0 は保存しない）。保存中は同じ検索語での検索を省く
search_cache_days = 30
# 曲の情報（タイトル・再生時間・サムネイル）を保存しておく日数（0 は曲名検索・プレイリストの結果も含めて保存しない）
track_cache_days = 183
# yt-dlp に渡す User-Agent（空欄なら yt-dlp 既定の最新ブラウザ UA を使用。通常は空欄推奨）
user_agent =
# Firefox でログインしている YouTube アカウントが Premium 会員か（yes / no / auto）
# yes か no を指定すると、判定のための通信を省いて曲の読み込みが速くなる。auto は毎回自動で判定する（低速）
# 実際と異なる値にすると音質の低下や再生失敗の原因になるため、不明なら auto のままにする
youtube_premium = auto
# SQLiteデータベースのファイルパス（相対パスは main.py のフォルダ基準）
database_path = data.db
# デバッグ出力（true / false）。true にすると各処理の所要時間（[PERF]）や内部処理の詳細もログに出す
# false ではエラー・警告と曲の読み込み状況など、運用に必要なものだけを出す
debug = false
# 毎日この時刻（HH:MM、24 時間表記）を過ぎてから、どのサーバーでも使われていないときに Bot を再起動する（空欄なら再起動しない）
# 長く動かし続けると曲の取得が遅くなるため、抽出用の子プロセスや Deno も含めて起動し直す。start.bat（start.ps1）から起動したときだけ有効
daily_restart = 00:00
```

| キー | 既定値 | 範囲 | 説明 |
|---|---|---|---|
| `default_volume` | `0.25` | 0.0〜2.0 | サーバーで `/vol` を未設定のときの音量 (1.0 = 100%) |
| `default_queue_limit` | `50` | 1〜50 | キューに入れられる最大曲数の既定値 (`/setting limit queue` で上書き) |
| `default_playlist_limit` | `10` | 1〜50 | プレイリストURLから1回で追加する最大曲数の既定値 (`/setting limit playlist` で上書き) |
| `default_alone_timeout` | `10` | 0〜600 | 聴者がいなくなってから自動で退出するまでの秒数の既定値。0 は自動退出しない (`/setting autoleave` で上書き) |
| `max_retries` | `3` | 1以上 | ストリームURLの取得に失敗したときの最大試行回数 |
| `max_worker_threads` | `2` | 1以上 | yt-dlp で曲を解析する子プロセスの数 (同時に解析できる曲数)。1 つあたり約 40MB。複数サーバーで同時に使う場合は増やす |
| `cache_ttl` | `14400` | 0以上 | プレイリストの取得結果を、取り直さずにそのまま使う秒数 (0 は毎回取り直す)。過ぎた後は、保存した1曲目を先に読み込みながら最新の曲順を取り直す |
| `search_cache_days` | `30` | 0以上 | 曲名検索の結果 (どの曲が見つかったか) を保存しておく日数。保存中は同じ検索語 (全角・半角や大文字・小文字の違いは同じとみなす) での検索を省く。保存した曲を再生できなければ検索し直す。0 は保存しない |
| `track_cache_days` | `183` | 0以上 | 曲の情報 (タイトル・再生時間・サムネイル) を保存しておく日数。期限を過ぎた分は起動時に削除する。0 は曲名検索・プレイリストの結果も含めて保存しない |
| `user_agent` | (空欄) | - | yt-dlp に渡す User-Agent。空欄なら yt-dlp の既定値を使用 |
| `youtube_premium` | `auto` | yes / no / auto | ログイン中の YouTube アカウントが Premium 会員か。yes / no を指定すると YouTube の曲の読み込みが約1秒速くなる。auto は毎回自動判定。実際と異なる値にすると、音質の低下 (Premium 会員で no) や再生失敗 (非会員で yes) の原因になりうる |
| `database_path` | `data.db` | - | SQLiteデータベースの保存先 (相対パスは `main.py` のフォルダ基準) |
| `debug` | `false` | true / false | true にすると、各処理の所要時間 (`[PERF]`) や内部処理の詳細もコンソールとログファイルに出力する |
| `daily_restart` | `00:00` | HH:MM / 空欄 | 毎日この時刻を過ぎてから、どのサーバーでも使われていない (再生中・キューあり・Bot のいるボイスチャンネルに人がいる、のいずれでもない) ときに Bot を再起動する。空欄で再起動しない。不正な値は `00:00`。`start.bat` / `start.ps1` から起動したときだけ有効 |

## 🚀 実行方法
`start.bat` をダブルクリックしてください。管理者権限の確認が表示され、**管理者の Windows ターミナル**の新しいウィンドウで起動します。(Windows ターミナルが無い場合はそのウィンドウで起動します。PowerShell 7 があれば優先して使用し、無ければ Windows PowerShell を使用します)
* Bot は管理者権限が必須です。管理者の確認を拒否した場合や、管理者でない PowerShell から `.\start.ps1` を実行した場合は起動しません。
* 同じフォルダの Bot が既に起動している場合は、二重には起動しません。

コマンドから起動する場合は、以下を実行します。

```bash
venv\Scripts\python.exe main.py
```

### 毎日の自動再起動
`start.bat` (または `.\start.ps1`) から起動すると、`config.ini` の `daily_restart` の時刻 (既定 0:00) を過ぎてから、どのサーバーでも使われていないときに Bot が自動で再起動します。同じウィンドウの中で起動し直すため、再起動後も管理者のままです。使用中の場合は、使われなくなるまで1分ごとに確認して待ちます。
`venv\Scripts\python.exe main.py` で直接起動した場合は、終了後に起動し直す仕組みが無いため再起動しません。

### 🔁 サインイン時に自動で起動する (Windows・任意)
`tools\autostart.bat` をダブルクリックすると、メニューから切り替えられます。(管理者権限の確認が表示されます)

| 番号 / 引数 | 内容 |
|---|---|
| 1 / `on` | 実行したユーザーがサインインしたとき (30 秒後) に、`start.bat` を管理者として起動するタスクを登録する |
| 2 / `off` | タスクを削除する (起動中の Bot は止めない) |
| 3 / `status` | タスクと自動サインインの状態を表示する |

* ウィンドウはサインインしたユーザーのデスクトップに表示されます。すでに起動中なら二重には起動しません。
* PC の再起動だけで (誰もサインインせずに) 起動させるには、Windows の自動サインインも有効にしてください。[Sysinternals の Autologon](https://learn.microsoft.com/sysinternals/downloads/autologon) を使うと、パスワードを暗号化して保存できます。
	* Microsoft アカウントの場合は、先に「設定 > アカウント > サインイン オプション」の「Microsoft アカウントには Windows Hello サインインのみを許可する」をオフにし、ユーザー名に Microsoft アカウントのメールアドレスを入力します。

### 終了方法
起動したウィンドウで `Ctrl + C` を押すと、ボイスチャンネルからの切断やデータベース接続の後片付けを行ってから終了します。
ウィンドウを閉じるなど、それ以外の方法で終了した場合も、曲の解析用の子プロセスは自動で終了します。

### 🌐 Bot の通信を優先する (Windows・任意)
`tools\net_priority.bat` をダブルクリックすると、メニューから切り替えられます。(管理者権限の確認が表示されます)

| 番号 / 引数 | 内容 |
|---|---|
| 1 / `on` | Bot (Python) と FFmpeg の通信に優先の印 (DSCP) を付け、Windows Update などの裏のダウンロードの帯域を制限する |
| 2 / `off` | 有効にする前の状態に戻す |
| 3 / `status` | 現在の設定を表示する |
| 4 / `check` | 再生中に実行すると、Bot の通信に実際に印が付いているかを確かめる |

* Bot を起動したまま切り替えられます。(再起動は不要です)
* 優先の印はルーターが対応している場合にだけ効きます。裏のダウンロードの帯域制限は PC の中で完結するため、ルーターに関係なく効きます。

## 🩺 トラブルシューティング
| 症状 | 対処 |
|---|---|
| 再生に失敗する・403エラーが出る | YouTube側の仕様変更の可能性があります。`venv\Scripts\python.exe -m pip install -U yt-dlp yt-dlp-ejs` で yt-dlp を更新してください。 |
| YouTube の曲だけ取得が遅い・失敗する | Firefox で YouTube にログインしているか、Deno に `PATH` が通っているか (`deno --version`) を確認してください。 |
| 音が出ない | FFmpeg に `PATH` が通っているか (`ffmpeg -version`) を確認してください。 |
| 起動時に `PrivilegedIntentsRequired` エラーが出る | Developer Portal で MESSAGE CONTENT INTENT を有効にしてください。 |
| スラッシュコマンドが表示されない | 招待URLのスコープに `applications.commands` が含まれているか確認してください。反映まで時間がかかる場合は、Discord を再起動してください。 |
| エラーの詳細を確認したい | `log` フォルダのログファイル (`bot.log`、過去分は日付付き) を確認してください。 |
| 再生開始が遅い原因を調べたい | `config.ini` で `debug = true` にして再起動すると、各処理の所要時間が `[PERF]` として出力されます。 |
